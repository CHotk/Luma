# Lume 規則總表

這份是給未來的自己看的。程式怎麼寫可以改，這裡寫的是**為什麼這樣定**。
改規則之前先看完這份，很多看起來多餘的限制都是踩過坑才加的。

最後更新：2026-09-11

---

## 一、單字的四種狀態

狀態不是存下來的欄位，是**每次即時算出來的**，判定只在
`lib/domain/models/word.dart` 的 `statusWith()` 一個地方。
其他任何檔案都不准自己寫判斷條件。

| 狀態 | 條件 | 標籤色 |
| --- | --- | --- |
| 掌握 | 見下面兩條進法 | 綠 |
| 未確認 | 從沒錯過，答對過但還沒到門檻 | 黃 |
| 待複習 | **錯過就算**，跟後來有沒有答對無關 | 棕 |
| 沒考過 | 從來沒被考過 | 灰 |

### 為什麼待複習是「錯過就算」

使用者 2026-09-11 明確講：「待複習本身就是有答錯過的就算，而不是沒答對過」。

先前的寫法是 `right == 0 && wrong > 0`，結果 `right=1 wrong=3` 那種字
四個池子都不收，永遠不會再出現。錯過的字本來就最該回來，
所以改成只看 `wrong > 0`。

### 為什麼待複習用棕色不用紅色

紅色是「剛剛答錯」那一刻的顏色。待複習是一個狀態不是一個錯誤，
天天看到一整排紅色會焦慮。沒考過用灰色，因為它不是問題，
只是還沒碰過，不該跟待複習搶注意力。

## 二、怎樣才算掌握

兩條路，走哪一條看它有沒有錯過。

**從沒錯過的字**：答對達到 `confirmRight` 次（預設 3）。

**錯過的字**：答對次數要達到答錯次數的 `recoveryRatio` 倍（預設 10）。

```
錯 1 次 → 要答對 10 次
錯 5 次 → 要答對 50 次，整個字總共被考 55 次
```

倍率訂得重是刻意的。錯過的字要能相信它真的會了，就得多考幾次。
兩個數字都能在設定裡改。

**掌握之後對錯次數繼續累加**，不會歸零也不會停止計數。
`rightNeededFor()` 回傳 0 只代表「不差了」，不是把資料清掉。

門檻調高之後，原本掌握但沒到新門檻的字會自動掉回去。
這是刻意的：門檻變嚴就該重新驗證。

## 三、一輪出什麼題

一輪十題，組成是：

| 來源 | 題數 | 參數 |
| --- | --- | --- |
| 沒考過的新字 | 7 | `newPerRound - pendingPerRound` |
| 待複習 | 2 | `pendingPerRound` |
| 回考未確認的 | 1 | `reviewPerRound` |

### 補位規則

哪一種不夠就用別的補，一輪的題數固定不變：

```
待複習不夠 → 補新字
新字不夠   → 補待複習
兩邊都沒了 → 補已經掌握的字
```

只有單字庫本身比一輪還小的時候才會缺題，那時候不會重複出同一個字。

### 排序

- 待複習：錯最多次的先回來，同樣次數挑最久沒考的。
  不然同一個字會一直霸著位置，其他錯過的字永遠輪不到。
- 回考與墊底：最久沒考的優先。
- 新字：洗牌。題庫是照字母排的，不洗牌會整輪都是同一個字母。

四個池子都用 `statusWith()` 判斷，不在出題規則裡自己寫條件，
不然狀態定義改了這裡會默默跟不上。

## 四、題型

三種，在設定裡切。預設只點選，打字題要自己開。

| 模式 | 內容 |
| --- | --- |
| 只點選 | 全部英翻中，按會或不會 |
| 混合 | 多數點選，少數幾題中翻英要打字，題數可調 |
| 只打字 | 每題都要打出來 |

出題規則只看 `effectiveTypeQuestions`，不自己判斷模式。

**會與不會兩顆都隨時能按**，不用先翻卡片。翻不翻由使用者決定。
打字題也有「不會」，按了直接判錯並揭開答案，不逼人硬湊一個錯的上去。

### 拼字判定

`lib/domain/spell_judge.dart`。三條規則是使用者決定的，不要因為
「好像太嚴」就自己放寬：

1. **不管大小寫**
2. **複數算錯**
3. **a 和 an 視為不同的字**

只做兩件事：去掉前後空白、把大小寫拉平。不做字根還原也不做複數還原。

## 五、每日上限

預設一天 5 輪或 15 分鐘，哪個先到算哪個。做滿就**真的按不下去**，
不是只跳提示。這是防止做過頭然後整個放棄的核心。

**偽裝模式不受這條管**（使用者 2026-09-11 決定）。理由是上班很無聊，
那段時間本來就想一直背。代價是首頁那個環只反映一般模式的份量，
總量要看總紀錄頁。

跨日自動歸零，只看年月日不看時分秒。

## 六、紀錄

### 只增不改

`lib/data/repositories/history_repository.dart`。這是整套資料的權威。

**單字上的對錯次數不是自己累加的，是從紀錄加總算出來的。**
這樣兩邊（對話與 App）各自出題各自追加，合併時去重就不會有人的紀錄被吃掉。

### 每答一題就寫一次

不是整輪結束才寫。中途關掉瀏覽器或被系統收掉都不會掉資料，
半輪也留得下來。整輪做完才補上真正的耗時，並計入今日用量。

### 合併去重看內容不看編號

指紋是「輪次＋單字＋時間＋對錯」。兩邊剛好用到同一個輪次編號
也不會互相蓋掉，因為內容不同就是不同的兩筆。

### 每一題記什麼

輪次、單字、對錯、作答時刻、想了幾秒、題型、打字題實際打了什麼、
是不是回考。

打字題留下輸入內容是刻意的：光知道答錯沒有用，
要看得出當初拼錯在哪個字母才學得到東西。

## 七、資料放哪

```
En 資料夾的檔案 ──手動複製進 assets──> App 自己的儲存
```

單向。App 的成績存在裝置裡，不會回寫檔案。

- 原生：App 私有目錄
- 網頁：瀏覽器 IndexedDB，清掉就沒了

打包資料帶版本號 `SeedSource.bundleVersion`。
**每次從 En 資料夾重新複製檔案進 assets 就要加一**，否則 App 不會去讀新內容。
忘了加會以為程式壞了。

同步時只更新靜態欄位（中文、詞性、階段、例句），**不碰對錯次數**，
那是算出來的。App 裡有、打包資料沒有的字一律保留。

---

## 八、其他規則

- **結果頁一定要把答錯和沒答出來的字全部列出來並附中文**，一個都不能漏，
  也不要附記憶點。使用者要的是答案清單，不是講解。
- **偽裝模式一律點選題**，跳中文輸入法在辦公室很顯眼。
- **單字分級只有四級**：國小、國中、高中、大學。曾經細分到小一小六，
  但那層沒有官方依據，猜出來的年級只會讓人誤以為很準。
- **首頁圓環底下每天一句話**，五十句輪完才重來，用日期算不存狀態。
  語氣刻意不熱血，要讓人覺得今天這樣就夠了，不是再多做一點。

## 九、參數一覽

全部在 `lib/domain/rules_config.dart`，設定頁改的是覆寫值。

| 參數 | 預設 | 意思 |
| --- | --- | --- |
| newPerRound | 9 | 一輪的前段題數，含待複習 |
| pendingPerRound | 2 | 上面那幾題裡有幾題抽待複習 |
| reviewPerRound | 1 | 回考未確認的字 |
| typeQuestions | 3 | 混合模式的打字題數 |
| quizStyle | 只點選 | 題型模式 |
| roundsPerDay | 5 | 每天最多幾輪 |
| minutesPerDay | 15 | 每天最多幾分鐘 |
| confirmRight | 3 | 沒錯過的字要答對幾次算掌握 |
| recoveryRatio | 10 | 錯過的字要答對幾倍才算掌握 |
