# 記帳功能構想（還沒開始做）

2026-10-02 使用者整理好的記帳核心想法，要求先記下來，之後做記帳功能時照這份
加上數值計算。畫面長相另有五版設計稿：`design-history/記帳功能設計/`（還沒挑）。

## 核心：帳戶 ＋ 交易 ＋ 對帳 三層

### 1. 錢分成帳戶，各自算

例如：中信活存、中信信用卡、現金。三種帳戶分開記、分開對帳。

### 2. 交易分三種，「轉帳」不算支出

- **支出／收入**：真的花掉或賺進來的錢，才算進「本月消費」。
- **轉帳（資金移動）**：帳戶之間搬錢，**不算支出**。
  - ATM 提款 NT$3,000 ＝ 中信活存 −3,000、現金 +3,000。之後拿現金買便當
    NT$120，那 NT$120 才是支出。
  - 繳信用卡費 NT$8,000 ＝ 中信活存 −8,000、信用卡負債 −8,000。**不能再算
    一次支出**，刷卡當下已經算過了，不然同一筆消費會被算兩次。
- 信用卡刷卡：信用卡負債 +295、餐飲支出 +295。

### 3. 對帳差額（抓漏記，這是重點功能）

不要求每筆都記到完美，讓漏掉的錢最後以「差額」浮出來。三種帳戶同一套邏輯：
**實際值（使用者偶爾輸入） vs App 從上次確認點推算的值**，差額＝沒記到的錢。

- **銀行**：上次確認餘額 ＋ 存入 − 提款 − 轉出 − 卡費 ＝ 理論餘額；跟實際
  餘額比。例：理論 32,500、實際 31,870 → 未記帳差額 NT$630。
- **信用卡（用即時可用額度）**：使用者確認過中信的「可刷卡額度」刷完立刻
  變動，所以拿來做核心對帳成立。
  - 已占用額度 ＝ 總額度 − 可用額度。
  - App 推算的占用變化 ＝ 刷卡消費 − 退款 − 繳卡費造成的額度恢復 ± 其他調整。
  - **不要**只用「月初可用額度 − 現在可用額度」，中間繳卡費、退款會讓額度
    回升，算出來會錯。
  - **也不要**把「總額度 − 可用額度」直接當成「本月消費」——那是占用，不是
    這個月花的（會含跨月帳單、分期等）。
  - 例：實際占用 27,500、App 推算 27,205 → ⚠ 信用卡可能漏記 NT$295。
  - **預授權**（飯店、加油站、租車會先占額度、最後不一定請款）：**不另外記**
    （2026-10-02 使用者決定交易不要 `status` 欄位）。它會先以信用卡差額出現，
    等真的請款再記實際金額，差額自己消失；請款前那筆差額暫時掛著，知道是
    預授權就好，不要急著記成支出。
- **現金**：上次錢包金額 ＋ 提款 − 記到的現金支出 ＝ 理論現金；跟實際錢包比。
  現金最容易漏，差額可以選「補記交易」或「直接調整成一筆未分類支出」，不用
  為了一杯飲料想破頭。

### 4. 首頁把兩件事分開

- **控制開銷**：本月消費、本月預算、剩餘可花（預算 − 已記消費）。
- **記帳完整度**：每個帳戶的差額（✓ 已對帳／⚠ 差額 NT$xxx）。

「剩餘可花多少」跟「漏記多少」是完全不同的兩件事，不要混在一個數字裡。

## 起始日，不強求補完歷史

選一天當起始日（例如 2026/10/01），輸入當天的三個期初值：銀行餘額、信用卡
目前占用／未繳、身上現金。對帳從起始日開始。手上的歷史刷卡紀錄能匯入就匯入，
拿來做過去消費分析，但不影響對帳。

## 貼上文字一鍵匯入

使用者手上的刷卡紀錄格式（之前從截圖轉出來的）：

```
中信銀行｜2026/09/24 21:34｜娛樂｜凱悅KTV新莊店｜NT$1,267
中信銀行｜2026/09/23 19:27｜餐飲｜foodpanda｜NT$295
中信銀行｜2026/09/22 10:40｜雲端服務｜綠界科技｜NT$125
中信銀行｜2026/07/27 19:02｜提款｜ATM提款｜NT$3,000
```

做一個「貼上多行 → 自動解析成交易」的匯入：欄位依序是 銀行｜日期時間｜分類｜
商家｜金額。分類是「提款」的要自動變成轉帳（活存 → 現金），不能算支出。

## 資料格式（定案，2026-10-02）

**存成 JSON**，照 App 現有做法存在本機 IndexedDB ＋ R2 雲端同步。不存 `.txt`：
欄位靠位置切容易被商家名稱裡的分隔符號弄壞、加欄位舊資料會對不上，也放不下
同步需要的 `id`／`updatedAt`／刪除標記。`.txt` 只當「貼上匯入」的輸入格式，
原始那行文字保留在交易的 `raw` 欄位。

**分 4 個檔、每個檔是一個清單**——一個檔一種資料，才能直接套日記／健身那套
清單同步合併（照 `id` 合併、比 `updatedAt` 新舊、刪除永遠贏）。

### 1. `ledger_accounts.json`：帳戶

```json
{ "id": "ctbc_card", "name": "中信信用卡", "type": "credit_card",
  "creditLimit": 100000, "order": 2,
  "createdAt": "...", "updatedAt": "...", "deletedAt": null }
```

- `type`：`bank`／`credit_card`／`cash`
- `creditLimit`：只有信用卡有
- `order`：顯示順序

### 2. `ledger_transactions.json`：交易（核心）

```json
{ "id": "6f1c9a2e4b7d4c1fa0e3b5d8c2a71f94", "type": "expense",
  "occurredAt": "2026-09-23T19:27:00+08:00",
  "amount": 295,
  "accountId": "ctbc_card", "toAccountId": null,
  "category": "餐飲", "merchant": "foodpanda", "note": "",
  "linkedId": null,
  "flagged": false,
  "paidFor": null,
  "source": "paste", "raw": "中信銀行｜2026/09/23 19:27｜餐飲｜foodpanda｜NT$295",
  "createdAt": "...", "updatedAt": "...", "deletedAt": null }
```

- `type`：
  - `expense` 支出、`income` 收入
  - `transfer` 轉帳：錢從 `accountId` 移到 `toAccountId`（ATM 提款、繳卡費都
    是這個，**不算支出**）
  - `refund` 退款：用 `linkedId` 連到原本那筆交易
  - `repayment` 別人還你錢：用 `linkedId` 連到當初幫人付的那筆（見下面 `paidFor`）
  - `adjustment` 對帳調整：例如現金差額直接調成一筆未分類支出
- `source`：`manual` 手動／`paste` 貼上匯入／`adjust` 對帳產生
- `raw`：貼上匯入時的原始那行，查來源用
- `linkedId`：退款、還錢用，指回原本那筆交易的 `id`；其他類型是 `null`
- `flagged`：`true`＝這筆要注意（2026-10-02 使用者要求：單純標註、不影響任何
  計算）。為什麼要注意寫在 `note`，列表上用一個小旗子標出來、可以只篩出被標記的
- `paidFor`：這筆有幫別人付錢（2026-10-02 使用者要求），沒有就是 `null`：

  ```json
  "paidFor": { "amount": 600, "people": "阿明、小華", "settled": false }
  ```

  - `amount`：幫別人付的部分（不能超過整筆 `amount`）
  - `people`：幫誰付，自由文字
  - `settled`：對方還清了沒

### 幫別人付錢怎麼算（`paidFor`）

例：聚餐刷卡 1,000，其中 600 是幫阿明、小華付的。

- **帳戶照整筆算**：信用卡真的刷了 1,000，對帳要用 1,000，不然會冒出假差額。
- **本月消費只算自己的**：1,000 − 600 ＝ 400 進「本月消費」跟分類統計，
  不然幫人付的錢會讓你以為自己花很多。
- **對方還錢**記一筆 `repayment`（例如阿明轉 300 到活存）：活存 +300 照算、
  對帳才會平，但**不算收入**（那是你的錢回來，不是賺的）。`linkedId` 指回聚餐
  那筆；全部還清就把那筆的 `paidFor.settled` 改成 `true`。
- **首頁可以多一個「別人還欠你」**：所有 `settled` 是 `false` 的 `paidFor`
  加總，扣掉已經連到它的 `repayment`，提醒你去收錢。

提款的樣子：

```json
{ "id": "…", "type": "transfer", "occurredAt": "2026-07-27T19:02:00+08:00",
  "amount": 3000, "accountId": "ctbc_bank", "toAccountId": "cash", "... ": "..." }
```

### 3. `ledger_checkpoints.json`：對帳點（使用者輸入的實際值）

```json
{ "id": "…", "accountId": "ctbc_card", "at": "2026-10-15T12:00:00+08:00",
  "balance": null, "creditLimit": 100000, "available": 72500,
  "note": "", "updatedAt": "...", "deletedAt": null }
```

- 銀行／現金填 `balance`
- 信用卡填 `creditLimit`＋`available`（已占用 ＝ 兩者相減）
- 差額 ＝ 這次的實際值 vs「上一個對帳點 ＋ 中間的交易」推算出來的值

### 4. `ledger_budgets.json`：預算

```json
{ "id": "…", "month": "2026-10", "category": null, "amount": 30000,
  "updatedAt": "...", "deletedAt": null }
```

- `category` 是 `null` 代表整月總預算，填了就是那個分類的預算

### 實作時要守住的規則

1. **金額用整數**（新台幣到元），不用小數——小數會有 0.1＋0.2≠0.3 的誤差，對帳
   差額會莫名差幾毛。
2. **金額永遠是正數**，方向由 `type` 跟帳戶決定。正負號混著用最容易寫出重複扣、
   少扣的錯。`paidFor.amount` 也是正數，而且不能超過整筆金額。
3. **時間帶時區**（`+08:00`），不然跨裝置、跨午夜的交易會算錯月份。
4. **`id` 用 32 位 UUID**（隨機產生的 v4、32 個十六進位字元、不加連字號，
   全部統一這個寫法），不用流水號——兩台裝置同時新增會撞號。
5. **只存事實，不存算出來的數字**：餘額、本月消費、差額都即時從交易＋對帳點
   算。存起來的話改一筆交易就得記得同步更新好幾個地方，很容易不一致。
6. **刪除用標記**（`deletedAt`），不直接刪——跟日記同一套，不然刪掉的交易下次
   同步會被別台裝置復活。

**資料量**：一年記 3,000 筆大約 600KB，整包同步很快。真的變大再改成一年一個檔。

## 跟這個 App 現有架構的關係

- 存放：照 App 現有做法，本機 IndexedDB ＋ R2 雲端同步（一個功能一個 JSON
  檔，見 `lib/data/cloud/r2_sync_service.dart`），交易要有 `updatedAt`／
  `deletedAt` 墓碑，跟日記、健身同一套合併規則。
- 原始構想裡提醒「不要把 R2 永久金鑰寫死在前端 JS」：這個 App 的 R2 金鑰是
  使用者自己在設定頁輸入、存在自己裝置上，不是寫進打包好的程式碼，所以沒有
  「任何人打開網頁原始碼就看得到」的問題；但金鑰還是存在瀏覽器裡，換裝置或
  清資料要重新輸入。
- 照專案慣例，記帳是獨立一份實作，不跟看盤／抽菸／喝酒共用設定或邏輯。
